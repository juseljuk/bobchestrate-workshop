Part 1: Custom LangGraph Agents for wxO 75–90 min • Core Lab

Build, package, and deploy native Python LangGraph stateful agents inside the watsonx Orchestrate runtime.

The Contract: Any LangGraph agent runs inside wxO as long as it exposes the entry point: create_agent(config: RunnableConfig) -> StateGraph.
1. Minimal Pipeline echo_agent
Verification of the uncompiled graph entry point contract and agent packaging without SDK complexity.
2. Pure LangGraph with LLM simple_llm_agent
Standard LangChain ChatOpenAI + Groq integration using secure wxO connection credentials.
3. wxO Native LLM Integration ChatWxO
Switching to the platform-native managed gateway for direct LLM invocation and tool calling.
4. Production Features research_agent
Dynamic ReAct tool-calling, API integrations, checkpointers for state, and cross-session user memory.

Key Takeaways & Best Practices

  • When to use LangGraph vs Native Agents: Choose LangGraph when you need custom graph topology (loops, parallel execution, custom state reducers) or are bringing existing code.
  • State & Runtime Rules: Only the messages key persists across turns; package size must stay under 50 MB; external calls use wxO Connections.
  • Accelerated with Bob: The pre-loaded wxo-langgraph skill assists in authoring platform-correct schemas, decorators, and configurations.
